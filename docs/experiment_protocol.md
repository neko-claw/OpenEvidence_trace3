# 赛道三实验协议（B4 对接版）

> 版本：v0.1
> 日期：2026-08-11
> 当前执行模式：课程最小可复现版

## 1. 实验目标

在高血压和血脂主题上，比较外部证据和检索增强系统对回答质量、证据支持性、拒答能力、延迟和成本的影响。

本轮重点回答：

1. 基础 RAG 是否优于 closed-book LLM？
2. rerank/MMR 是否改善最终证据选择？
3. 完整组件包是否相对 rerank RAG 带来净收益？
4. 检索质量下降时，系统是否会被错误证据拖累或正确拒答？

## 2. 实验条件

| 条件 | 名称 | 是否提供项目 Evidence | 主要用途 |
|---|---|---:|---|
| A | closed-book LLM | 否 | 测量模型自身知识和推理能力 |
| B | fixed RAG | 是，固定初检结果 | 测量外部证据接入的增量 |
| C | rerank RAG | 是，B 的同一候选集经 rerank/MMR | 测量排序和去重增量 |
| D | full system | 是，C + Wiki/Skill/MCP/Agent | 测量完整组件包整体增量 |
| E | degraded RAG | 是，C 候选集经过预注册劣化 | 测量检索失败和拒答能力 |

A2 通用搜索对照本轮暂不执行，后续如有预算再增加，不影响 A-E 主实验。

## 3. 公平性控制

A-E 使用：

- 同一生成模型和模型快照；
- 同一温度和最大输出 token；
- 同一中文回答结构和安全边界；
- 同一超时、重试和缓存规则；
- 同一题目文本和运行时间窗口；
- 固定的语料、数据集和索引版本。

A 不提供 Evidence，因此 citation coverage 对 A 标记为 `not_applicable`，不计为 0。B-E 的引用必须来自对应运行实际获得的 Evidence 白名单。

B/C 必须使用相同的初检候选集；C 只能改变 rerank/MMR。D 的新增编排必须记录额外工具调用、延迟、token 和成本。D 只解释为完整组件包的整体差异，不对单个组件做因果归因。

## 4. 数据分片

当前默认采用课程最小可复现版：

| 分片 | 数量 | 用途 |
|---|---:|---|
| DEV | 30 | 选择 top-k、rerank、MMR 和拒答参数 |
| TEST | 40 | A/B/C/D 主实验 |
| STRESS | 20 | C/E 劣化和检索诊断 |

正式实验开始后，TEST 题、gold、qrels、Prompt 和索引版本冻结。若后续资源足够，可将 TEST 扩展到 60 道，但不能用扩展后的题目替换已经运行的低分题。

## 5. E 条件主劣化规则

本轮 E 采用 `drop_gold_v1` 作为主规则：

1. 先运行 C 的固定初检和 rerank；
2. 只在 STRESS 题中选择至少命中一个 gold Evidence 的运行；
3. 从 C 的候选集中删除排名最高的 gold Evidence；
4. 其余候选、模型、Prompt 和生成参数保持不变；
5. 重新生成并记录是否出现错误、无支持主张或合理拒答。

如果题目没有命中 gold，不进入该条 E 主分析，记录为 `not_applicable`，不使用临时 fallback 规则改变实验口径。

“注入主题相关但不支持主张的证据”作为后续 `stress_inject_v1` 扩展，不与 `drop_gold_v1` 合并成一个分数。

## 6. 主要输出指标

B4 负责提供检索和运行原始记录，B5 负责最终评分和统计。B4 至少输出：

- Hit@5、Recall@50、MRR；
- nDCG@8；
- 初检和 rerank 后的候选快照；
- 最终上下文 Evidence ID；
- 检索延迟、生成延迟、token 和估算成本；
- 工具调用轨迹；
- E 的扰动前后候选集。

## 7. 禁止事项

- 不得在 TEST 题上调 rerank 权重或 top-k；
- 不得根据模型输出事后选择 E 的扰动规则；
- 不得静默丢弃超时、错误或非法输出；
- 不得把 D 的差异归因给 Wiki、Skill、MCP 或 Agent 中的单个组件；
- 不得把自动 judge 作为唯一医学金标准。

## 8. B4 完成标准

- C、D、E 有统一运行入口；
- 断网时可以使用 fixture 完成运行；
- C 保存完整检索链路和特征分数；
- D 保存 Agent plan、Skill 和 MCP tool trace；
- E 的删除规则和 seed 可复现；
- 所有运行都生成完整 Run JSONL；
- 至少形成一个 RAG 获益案例和一个检索拖累/合理拒答案例；
- 结果可以直接交给 B5 评分。
